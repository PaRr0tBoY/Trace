# 36 — 任务状态机重构

**What to build:** 任务状态从"多 active + paused 自动恢复"改为五态状态机：全局唯一 RUNNING、WAITING 系统休息态、PAUSED 用户手动且免疫自动恢复、COMPLETED / ARCHIVED 仅用户操作。状态带来源与原因，UI 可区分"你暂停了"与"系统判断等待中"。旧数据迁移：多 active 只保留最近活跃者为 RUNNING，其余降 WAITING（来源=system）。这是预期内的行为变化（旧 spec 的"多任务同时 Active"与冻结架构冲突）。

**Blocked by:** 无

**Status:** ready-for-agent

- [ ] 状态转换表：合法转换全绿，非法转换被拒（COMPLETED 不可自动复活、PAUSED 不被自动恢复、ARCHIVED 不可自动复活）
- [ ] runningTaskCount ≤ 1 由域层 transition 强制（任何路径都绕不过）
- [ ] statusSource（user / system）+ statusReason 随状态变化写入并推送
- [ ] UI 状态标签可区分"你暂停了"与"系统判断等待中"
- [ ] 迁移：旧数据多 active 场景处理后恰好一个 RUNNING（最近活跃者），其余 WAITING
- [ ] vitest 全转换表 + 迁移测试；typecheck + npm test 全绿
