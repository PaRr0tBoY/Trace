# 长期记忆系统规格

Type: grilling
Status: resolved

Blocked by: 07

## Answer

### 决议（2026-08-11 grilling，用户逐项确认）

**1. 存储：memories.json + 可选 embedding**

- memories.json（userData，与 tasks.json 同模式，带 version 字段）；零新依赖。
- embedding 通道复用 10 的选型（本地模型，如 bge-small-zh-v1.5 26-48MB），缺失时纯文本/规则检索降级（隐私铁律极端情形成立）。

**2. 分类与 schema：四类 + 反馈分流**

- 四类：identity（职业/技能/领域）、tool（工具偏好）、project（长期项目及关联）、workflow（工作流模式：应用序列/节奏）。
- 任务系统反馈（确认的标题、忽略的模式、聚类反馈）自动沉淀为 project/workflow 候选（source: 'task-feedback'，userState: 'suggested'）——仍需用户确认才成为 confirmed。
- Memory = { id, type, content, confidence, hitCount, lastSeenAt, createdAt, source: 'ai-suggest'|'task-feedback'|'user', userState: 'confirmed'|'suggested'|'ignored'|'banned' }。

**3. 写入确认：联动建议引擎 + 候选面板**

- 候选产生：用户确认任务/聚类反馈时顺带提取（如确认"开发 CAD Agent"任务 → 提议"长期项目：CAD Agent，涉及 Code/Chrome"）；无独立检测管线。
- 记忆面板（设置内）：候选 + [保存]/[忽略]/[永久禁止]。
- banned 表：关键词/类型匹配，之后同类不再提议（与 07 的忽略签名表同级机制）。

**4. 强化/衰减：频率×时效 + context-prior**

- 强化：用户确认/相关事件命中 → hitCount+1、confidence 更新：conf = sat(hitCount) × exp(-λΔt)，λ 周级（与 10 聚类时间衰减一致）。
- 衰减：超 N 天未命中降权；超 N 天 + 低分 → 清理候选（用户确认后删除）。
- 使用（context-prior）：建议引擎分析时，命中任务/事件的记忆（project、workflow）注入聚类判定与标题生成——提升置信度、标题贴合用户术语（LLM 辅助层输入的一部分）。
- 阈值（N 天、λ、分数下限）进设置，默认值标注依据（λ 周级来自 10 的聚类先例）。

**5. 与 screenpipe 的关系**

- 无（screenpipe 已后置）；02 调研中的记忆设计参考（Mem0/Letta 分层）已融入本决议（四类 = 结构化记忆；suggested/confirmed = 提取+确认流程）。
