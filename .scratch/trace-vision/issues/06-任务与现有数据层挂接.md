# 任务与现有数据层挂接

Type: grilling
Status: resolved

Blocked by: 01, 05

## Answer

### 决议（2026-08-11 grilling，用户确认 + 一项自定义转向）

**1. 剪贴板自动归属（用户转向：按复制来源进程归属）**

- 剪贴板捕获时（现有 ClipboardWatcher 600ms 轮询），取当前前台进程（05 的 L0 轮询已跟踪 latestForeground）作为复制来源；该进程匹配任务 AppRef → 链接到该任务（快照写入 resources）；无匹配任务 → 不自动链接。
- 多任务共享同一应用时的消歧：匹配任务中 lastActiveAt 最近者（与 01 的"最近活跃优先"一致）。
- 归属是规则（非 AI）、可解释（"从 Code 复制 → 任务 X"）；设置开关默认开，可关退化为纯手动。
- 事件日志扩展：新增 `{type:'clipboard', appName, ...}`（05 事件日志的补充，07 聚类可用）。

**2. 关联交互：双向拖拽 + 按钮（用户确认）**

- 面板内 HTML5 DnD：剪贴板层条目拖入任务卡片/详情 → task:link-item。
- 任务详情 [＋添加内容] 从剪贴板层挑选。
- 反向：任务资源条目 OLE 拖出（复用现有 item:start-drag 通道——资源条目映射回 item 内容或临时文件）；点击 → 置顶到剪贴板层（item 存活时）。
- alive=false 的条目不可拖出（占位"已从剪贴板移除"）。

**3. 快照：轻量快照 + alive 标记（用户确认）**

- 文本 = preview 200 字符（不存全文，item 存活时详情从 ItemStore 读全文）；图片 = imageId + width/height/bytes（已核实 ItemStore.trim 会 removeImageFile 删 PNG——驱逐后显示占位）；文件 = paths 列表（磁盘文件不受驱逐影响）。
- alive 标记：推送 TaskDto 时查 ItemStore 计算（无额外通道）。
- 快照关联时一次性生成；dedupe 提升（hitCount++）不刷新快照（内容未变）。

**4. DTO 与 IPC：全量推送 + invoke 通道（用户确认）**

- state:tasks 全量推送 TaskDto[]（与 state:items 同模式：Main 推送为唯一真实来源，renderer Zustand 视图缓存）；TaskDto = Task + resources 内联（含 alive）。
- invoke：task:load / task:create / task:update / task:delete / task:merge / task:link-item / task:unlink-item。
- 四文件合约（ipc.ts / bridge.ts / preload / main-ipc）。

**5. 迁移与兼容**

- tasks.json 全新文件，items.json 不动，无数据迁移；去重签名与任务关联不冲突（任务持有 itemId 引用，独立于签名去重）。
- 反向查找（item → 任务）：扫描（任务量小）。

**6. 依赖**

- 01（模型）、05（前台进程跟踪作为复制来源）、07（聚类消费 clipboard 事件）、09（规格整合）。
