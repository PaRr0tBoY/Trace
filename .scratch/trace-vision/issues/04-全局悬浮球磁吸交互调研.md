# 全局悬浮球磁吸交互调研

Type: research
Status: resolved

## Answer

- 可行：CursorBuddy（开源 Electron 跟随悬浮窗）验证了"主进程轮询 + 每帧 setPosition + spring 物理"路线；Trace 现有 16ms 轮询频率即该方案基准。逐帧 setPosition 的抖动坑只在"IPC 传 bounds 而不真正 setPosition"的反模式里，main 进程内做动画即可规避。
- 结构：球应为独立小窗（~48px、click-through + focusable:false），展开时隐藏球、现有 384px 面板窗弹出；不合并、不做窗口级尺寸动画。磁吸用 velocity 档位判定（<2px/ms 有意、>10px/ms 路过）+ 方向感知宽限；Framer 磁吸模式（useMotionValue + useSpring，falloff = 1-dist/radius）可直接参考。
- 平台限制须写进规格：'screen-saver' 置顶对独占全屏游戏无效（Discord 靠独立原生应用实现 overlay）；Electron 34 处于 SysDragImage 拖拽幽灵泄漏 bug 影响区间（37→41 修复）；混合 DPI 多屏 setPosition 有历史偏移问题（需 workaround + 实机验证）。

详见：`research/04-全局悬浮球磁吸交互调研.md`（相对本文件：`../research/04-全局悬浮球磁吸交互调研.md`）

## Question

Windows/Electron 上实现愿景 V2"右下角圆球跟随鼠标 + 左缘磁吸 + 吸附展开 + 移开弹回"的可行方案，供规格的 V2 章节使用（聊天记录假设 macOS，本 ticket 按 Windows 重新论证）：

- **全局跟随**：光标轮询（现有 16ms `screen.getCursorScreenPoint()` 模式）驱动透明小窗逐帧 moveWindow 的延迟/抖动/闪烁问题；与 DPI 缩放、多显示器的交互。
- **与现有边缘窗口架构的关系**：现有 384px 透明置顶窗口（koffi 光标轮询、置顶心跳、detector window、OLE 拖拽暂停心跳）——圆球是独立小窗还是合并进现有窗口体系？点击穿透（setIgnoreMouseEvents）与常驻跟随的冲突？
- **磁吸动画**：Framer Motion（已用）在渲染层做"吸附-展开-弹回"动画的可行性；物理感（距离 → 力）的呈现方式。
- **已知坑**：全屏应用下的层级（'screen-saver' 置顶）、任务栏/多显示器边缘、OLE 拖拽期间的冲突、误触防护（聊天里提过 velocity 阈值）。
