## 实施记录（2026-08-13，Ticket32NativeDeps）

### 版本与维护状态（采用前核实）
- **better-sqlite3**：7,426 star；最新 **13.0.3**（2026-08-05）。但 v13 改用 NAPI_VERSION=10（prebuildify + `prebuilds/`），**与 Electron 34 的 Node 20.19（N-API 9）不兼容**：
  - 实测矩阵：Node 24（napi 10）require+建库 OK；Node 20.19.1 与 Electron 34.5.8（均 napi 9）在首次 `new Database()` 处硬崩溃（exit 3/5，无 JS 错误）。
  - 本地用 node-gyp 从源码对 v13 重编译（MSVC 工具链可用）后同样崩溃；改为 NAPI_VERSION=9 编译连 Node 24 都崩（node-addon-api 8.9.1 的 Symbol::WellKnown 路径）。
  - **结论：v13 与 Electron ≤ 34 根本性不兼容，只能升级 Electron（napi 10）或降级。**
  - **采用 better-sqlite3@12.11.1**（2026-06-15 发布，NAN 系，v12 线仍维护；npm 无 12.12.0，仅有 GitHub tag）→ `electron-rebuild -f -w better-sqlite3` 对 Electron 34 重编译 → Electron 内 require + 建库读值 OK（ABI 132）。**副作用：该二进制为 Electron ABI，纯 Node（vitest）下 require 会报 ABI 不匹配（137≠132）—— 后续数据层单测需在 Electron 运行时跑或另行处理（已向 coordinator 说明）。**
- **node-llama-cpp**：2,153 star（handoff 估计 ~6k 不实）；最新 **3.20.0**（2026-08-11）。走 N-API 平台包机制：`@node-llama-cpp/win-x64` 内 `llama-addon.node` + llama.cpp DLL，主包 `bins/` 只有 `.moved.txt` 标记。**Electron 34 内 import + getLlama() 均 OK**（N-API 9 兼容）。自带 asar 支持（`resolveActualBindingBinaryPath` 把 `.asar\` 改写为 `.asar.unpacked\`）。
  - 注意：自动 GPU 探测会先试 Vulkan（utilityProcess 子进程测试），失败后优雅回退 CPU；打包产物已排除 cuda/vulkan 变体（-258MB），回退路径同样适用。
