## Design Context

### Users

- **Primary**: the developer (Acid), power user, uses the panel dozens of times per day as its own clipboard manager. Also ships to a small user base of clipboard-heavy desktop users (designers, developers, writers).
- **Context**: always-on-top edge blade on Windows. Zero-click interaction — hover to open, click/paste/drag to use. Sessions are short and frequent (open → act → leave, seconds at a time).

### Brand Personality

- 暗黑精密机械感 (dark precision-mechanical): calm, restrained, fast, zero-noise. Animations behave like precision instruments — crisp damping, a hint of spring, never showy.
- References: BoringNotch / Apple Dynamic Island (overshoot-and-settle, content stays still while the shape moves), mechanical audio haptics (dial ticks, toggle snaps — already in soundEffects.ts).
- Anti-references: bouncy/elastic easings, confetti, glassmorphism glow, anything that draws attention to the animation itself.

### Aesthetic Direction

- Pure black (#000) surfaces, thin 1px white-ish dividers, one accent color (themeable). Typography-driven, no card-in-card nesting.
- Motion: compositor-only (transform + opacity + promoted clip-path). 60fps on 4K. Fast entrances (≤300ms), subtle micro-feedback (≤200ms), exits faster than entrances (~75%).
- Reduced motion is an **app-level choice** (two levels: standard/extended), NOT tied to the OS "Show animations" flag — the OS flag on the author's machine silently killed all animation once; the app must never do that again. Default = standard.

### Design Principles

1. **Motion communicates state, not decoration.** Every animation answers "what changed?" (opened, copied, pinned, selected, new content arrived). If it doesn't, it doesn't exist.
2. **The shape moves, content stays.** Follow BoringNotch: animate the container/background shape; never scale or slide content that carries information (text, lists).
3. **Fast is default.** Feedback ≤200ms, state changes ≤300ms, entrances ≤500ms. Exit = 75% of enter. One well-orchestrated reveal beats scattered micro-motion.
4. **Performance is a hard constraint.** Only transform/opacity/promoted clip-path. Gate expensive effects by item count (12-card enter limit, 30-card FLIP limit). Infinite loops + drop-shadow filters are the known jank source — keep them off or gated.
5. **The user owns the motion level.** standard = crisp functional motion (reveal, card enter/exit, flyouts, toasts, hover); extended = standard + delight (open bounce, tab-capsule spring, view slide, new-item highlight, empty-state entrance, badge pops, press feedback, copy ripple, indicator breathing). OS prefers-reduced-motion is ignored by design (documented in useOpenBounce); the in-app setting is the single source of truth.

### Mechanism Notes (verified 2026-08-14, framer-motion 11.18.2)

- `MotionConfig reducedMotion="always"` only snaps **positional keys** (transform family + width/height/top/left/right/bottom) — **opacity springs survive it** (verified: opacity 0.74 mid-flight under "always"). The two-level refactor deleted the minimal level and with it `MotionGlobalConfig.skipAnimations` — `reducedMotion="never"` stays pinned (explicit: OS flag never consulted).
- One source, per-mechanism gates: `settings.motionLevel` → CSS `data-motion` (extended-only rules under `:root[data-motion='extended']`, e.g. .act press scale) · Framer per-component `=== 'extended'` checks (bounce values, capsule spring vs 0.14s tween, flash, badge, ripple) · GSAP own gates (LiquidOctopusLoader, CopyIndicatorCurve icon breathing). `useAdaptiveSpring`/`useSubtleSpring` are DPR-only now (no motionLevel branch).
- Card enter animations are un-staggered (user rejected stagger as invisible); enter is a uniform 0.3s spring per card, capped at 12 cards via `ENTER_ANIM_LIMIT`.
- New-item highlight is a **shimmer sweep**: a blurred accent band (`filter: blur(5px)`) translating `x: -120% → 250%` in 1.4s, triggered on first panel open after a capture (once per `capturedAt`, 4s window). Copy-button clicks **suppress** it (ripple already communicates the copy): `suppressFlashUntil` stamps the copy time; the effect still marks `lastFlashedAt` so reopening never re-flashes.
- Copy ripple is Material-style: it starts at the clicked button's coordinates (`getBoundingClientRect` delta from the card) and expands `scale: 0 → 15` (28px circle → ~420px, covers any card) inside a `borderRadius: 16, overflow: hidden` clip, 0.65s. `rippleOrigin` is a state set in `onCopy`, so it survives `copied` reset.
