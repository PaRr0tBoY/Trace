# AI 建议引擎与 Provider 抽象规格

Type: grilling
Status: resolved

Blocked by: 01, 03, 05

## Answer

### 决议（2026-08-11 grilling，用户逐项确认 + 两项转向）

**1. 触发：静默期触发（用户确认）**

- 事件缓冲 ≥5 条新事件（可配）且静默 ≥60s（可配 30-300s）→ 触发一次分析。
- 建议卡不打断：展示在面板任务层顶部 + 状态徽标；参数进设置。

**2. 聚类策略（用户转向：算法聚类 + LLM 辅助）**

- 架构分层：规则预筛（事件批 app 名与任务 AppRef 重叠 → 候选任务）→ **算法聚类层**（纯算法归属判定；具体算法/embedding 选型、跨任务切分、增量更新由「任务聚类算法调研」ticket 10 落地）→ **LLM 辅助层**（只做标题生成、原因解释、低置信度标注；不承担归属判定）。
- 置信度：算法层输出归属置信度；LLM 补充标题与理由。
- 可解释性：建议卡显示算法证据（app 组合/时长/重叠任务）+ LLM 通俗理由。
- 与 01 衔接：确认 → merge 候选任务或新建。

**3. 忽略去重：本地签名表（用户确认）**

- 签名 = hash(app 组合 + 时段)；ignored.json（userData，LRU 上限 200）；建议前查重跳过；LLM 保持无状态。

**4. Provider 抽象（用户选定：多 provider 自动降级）**

- 统一 OpenAI 兼容 /v1/chat/completions；provider 链（主+备，每项 baseUrl/apiKey/model/kind）；失败自动切备（仅限已配置链内——用户配置云端 key 即视为同意其参与兜底）；全链失败 → 本次跳过、下静默期重试，设置页显示状态。
- 结构化输出两层降级（03 事实）：schema 合约 → json_object + prompt 内嵌 schema；客户端 JSON 校验 + 有限重试（strict 也会因 max_tokens 截断失败）。
- 无 LiteLLM；openai npm SDK（自定义 base_url）或 ~100 行 fetch 层。
- 设置 UI：provider 列表（本地/云端）+ 优先级排序 + 测试连接。

**5. 建议卡交互（01 主体 + UI 语义）**

- 卡片：可编辑标题 + 涉及应用 chips + 置信度 + 原因（算法证据可展开）+ [确认][编辑][忽略]。
- 确认 → merge/新建（01）；编辑 → 改标题后确认；忽略 → 丢弃 + 签名入表。

**6. 失败与边界**

- 未配置 provider / 全链失败 → 建议层静默降级，任务系统照常（采集与状态机是规则，不依赖 AI）。
- V1 无外部向量库；若 10 推荐 embedding 则用本地模型（Ollama），不上云。

**7. 依赖**

- 10（任务聚类算法调研，算法选型落地）；09（规格整合时并入）。
