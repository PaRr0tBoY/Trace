# ADR-0003: AI 标题生成并入保存按钮

- 状态：已接受（2026-08-11，grill-with-docs 会话）
- 关联：ADR-0002（引导流）、suggestionEngine.suggestTitle 现状

## 背景

原需求草案是"AI 建议按钮放保存按钮旁、只显示图标"；grill 中用户改版：**取消独立建议按钮**，
AI 标题生成并入保存按钮。理由：标题是保存的必需字段，与其让用户先点✨再点保存，不如一次
保存触发。同时明确"不要从 0 开始建议"——没有任何输入时 AI 不该凭空生成。

## 决策

### 保存按钮的三种路径

1. **标题非空** → 直接保存，不调 AI。
2. **标题为空，但 选中进程/选中剪贴板/备注 至少一项非空** → 先调 `task:suggest-title`
   生成标题，用最佳候选保存。
3. **四项全空** → 保存按钮禁用（无任何可依据的内容，与"不从 0 生成"一致）。

### AI 上下文（SuggestTitleContext 扩展）

= 标题 + 选中进程名 + 选中剪贴板条目预览 + 备注 + 命中记忆。
记忆注入复用建议引擎的 `matchMemories` 规则：仅 confirmed 的 project/workflow 记忆，
子串匹配文本 = 选中 app 名 + 选中条目预览 + 标题 + 备注，命中项作为 `memoryContext`
进入 LLM payload。编辑模式下已关联 resources 的预览一并携带（现有
`buildResourcePreviews` 已有此能力）。

### 失败兜底

生成失败（无 provider 配置 / 调用失败 / 超时 / 返回畸形）时**静默降级为算法标题**
（"X + Y task"，全空场景不适用故无 "Untitled task" 分支），不阻断保存、不 toast。
算法标题路径与建议引擎的 `algorithmicTitle` 同源。

## 后果

- 交互面缩小：一个按钮两种语义（保存 / 保存前先问 AI），无独立 ✨。
- 生成失败不打断流程：用户几乎永远能保存成功；标题不满意可在编辑模式改名。
- 保存的失败面只剩"保存本身失败"，与现状一致。
