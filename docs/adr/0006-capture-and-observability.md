# ADR-0006: 数据摄取与可观测性改造（UIA 摄取 / trace 契约 / 工作台 / 任务质量 / 智能初始页面）

- 状态：已接受（2026-08-14，grill-with-docs 会话）
- 关联：ADR-0005（架构原则：活动 → 决策 → 记忆流水线）；ADR-0004（导航 / landing / restore）；spec（Trace AI 管道重构规格）；`docs/computer-history.md`（ChatGPT Computer History 产品拆解）；`docs/dia-browser-research.md`（Dia 预测工作功能调研，2026-08-14 深调研折叠）

## 背景

本波改造由 grill 会话（2026-08-14）产出，围绕用户五个观察展开：

1. **黑盒**：任务系统全流程不可见，用户不知道数据怎么进、算法怎么处理、结果去哪；"AI 依据"在绝大多数任务上恒空（含 AI 直接挑选并重命名的任务），导出按钮灰置——事后定位为三层断链（见决策 5）。
2. **摄取未落地**：设计模仿 screenpipe（a11y 树优先、OCR 兜底），但 a11y（Windows UIA）零落地，OCR 只在分析触发时现抓、不持久化；窗口标题无信息时无兜底。
3. **任务质量低**：琐碎（秒级操作成任务）、宽泛（"终端与视频浏览"）、双主题（"Obsidian 浏览 AI 副业与小红书 wiki"）、非任务（娱乐内容）四类坏候选占比高；相同标题任务仍重复进候选。
4. **实时性差**：候选推送受静默期门控、L1（指示器提醒）从不出现（升级链要求"必须先展示过"）。
5. **想要的东西缺失**：用户画像填写 UI（spec 承诺未落地）、智能初始页面（按内容事件预测视图）、实时数据工作台（横切图 + 标记 + golden 审查，替代 JSON 硬编辑）。

本 ADR 记录上述全部设计决策；实现细节（阈值初值、冷却时长、打分表分值等）默认进算法层常量，可成长调优，不逐项进本 ADR。

## 决策

### 一、摄取层

#### 1. UIA 事件驱动采集（UIA 优先、OCR 兜底）

摄取主源为 Windows UI Automation（UIA）**事件驱动语义采集**，与 Computer History 的 macOS Accessibility 路线同构（事件流而非截屏）：焦点变化事件（`AddFocusChangedEventHandler`）、文本变化事件（`TextPattern` TextChanged，diff 拿增量）、前台窗口元数据（复用现有 koffi 前台轮询，后续可换 `SetWinEventHook` 减轮询）。锁屏/切用户/UAC 安全桌面硬暂停（`WTSRegisterSessionNotification`）；UIPI 提权窗口（管理员权限窗口的 UIA 树不可读）**放弃读取**，标题级兜底，不上 UIAccess。

**排除前置**：名单规则在事件落盘前执行（Computer History/skysight 模式），被滤事件留 suppression 记录不留内容；与隐私三权（ADR-0005 原则 7）一致，被拒数据落 trace `kind='privacy'`。

#### 2. 摄取阶梯（Capture Ladder）

内容摄取按可用性分级降级，每级都确定性、免费：

```
标题（窗口标题，512 字符）→ UIA 事件（焦点元素/文本增量/标签列表）→ OCR（隐私门后，分析时前台窗口）→ 材料信号（剪贴板复制）
```

低信息窗口（标题 = 应用名或空）触发 OCR 兜底；**不猜原则**：低信息窗口的活动归因降权（zone 降档），宁可不归因不误归——误归比不归更伤。UIA 读不到的内容（自绘 UI、网页正文）最终落 OCR。

#### 3. multiTabAdapter（多标签软件通用模块）

浏览器/IDE 等单应用多标签软件按通用抽象处理，归一化"当前标签上下文"：

- 浏览器 = **窗口标题（即当前激活标签标题，`GetWindowTextW` 现有机制）** + OCR 兜底（页面正文 UIA 读不到——Chrome 只在辅助技术请求时暴露 a11y 树）
- IDE = UIA TextPattern / 窗口标题
- 兜底 = 窗口标题

切换标签 → 标题变化 → app-switch 事件（pid 同、标题异）→ 段边界，时间线天然有标签级粒度。**不做 MV3 浏览器扩展**（out of scope）；网站级 URL 规则随之挂起（无 URL 数据源，标题启发式兜底）。

#### 4. 黑白名单双模式

设置新增"监控名单模式"：**黑名单（全收拉黑，默认，兼容现有 blockedApps）| 白名单（全拒收录）**。**两个名单独立持久化**，切换不丢失、切回继承。名单粒度为应用级（exePath/进程名）；排除变更只影响未来，不清算存量。白名单模式下"名单外应用停留超阈值 → 提示加入"的自动发现为可选补充。排除某来源时可手动触发**级联清除该来源历史记忆**（依赖决策 21 溯源链；不自动执行）。

### 二、AI 依据与 trace 契约

#### 5. AI 依据修复（P0）

"AI 依据恒空"根因三层断链，全部修复：

- **引擎分析路径（Path A）零 trace 写入** → `runAnalysis` 为每个候选生成 decisionId 并写 `observed` 行（活动摘要）；`suggestTitle` 写 trace（`model` kind，决策 6）——AI 挑选与重命名全程可追溯
- **采纳时不 rehome** → accept 时 `UPDATE trace SET taskId=? WHERE decisionId=?` 全链迁到新任务（对 Path A 无链场景由上一条补齐后同样成立）
- **提案卡 trace 入口 id 兜底** → 去掉 `decisionId ?? suggestion.id` 兜底，直接按 decisionId 查

#### 6. trace 契约扩展：算法 / 模型中间态

trace 现有五类 kind（observed/recall/decision/result/privacy）不足以支撑横切图——优化器的过滤/草稿/rerank 与 provider 的请求响应只进 ai-log.jsonl。新增：

- `algorithm`：聚类/分级/优化器中间态（候选分、过滤命中断言、rerank 结果）
- `model`：本地/云端请求摘要、思考、响应、标题草稿（含 suggestTitle）

payload 存**结构化要点不存全文**（提示词、完整响应继续进 ai-log.jsonl）；`decisionId` 贯穿；保留期沿用 30d，**被用户标记的数据豁免过期**（与任务同生命周期）。

### 三、工作台

#### 7. 开发者模式 + 独立服务

工作台 = 独立 localhost HTTP + WebSocket 服务，**仅在"开发者模式"开启时启动**（设置开关，默认关），不因此做任何面向用户的功能改动。安全：仅 loopback + 随机 token URL + Origin 校验。数据流：订阅现有 eventBus + trace 表增量（应用层 after-insert）→ WS 推送；冷启动先拉全量再增量。

#### 8. 三视图

- **实时流（横切图）**：数据进 → 每道关卡（摄取/聚类/资格门/分级/决策/模型调用/记忆写入）→ 结果 → 去向，一关一关展示，语义清晰
- **历史时间线**：按天分组的活动摘要条目（标题/摘要/来源应用/删除粒度 10min·1h·1d·all），Computer History 同款 UX；数据复用 segment/cluster/evidence
- **记忆**：过程视图（怎么获得/处理/整理）+ **全貌视图**（当前完整记忆库：episodes/entities/facts 全量 + 权重/状态 + 搜索）

#### 9. 标记交互与评审循环

标记对象 = **实时数据流为主 + golden 种子为辅**（golden 从历史提取，作回归不作日常调参料）。交互四步：①好/不好 → ②不好是哪个方面（标题建议/分级/归因/记忆/…）→ ③原因单选（琐碎/宽泛/不够具体/双主题/非任务/应用名进标题/贪心合并/隐私，即评审原因词汇表）+ 自定义 → ④落库并汇入评审报告，报告可导出（agent 可读）→ 算法/prompt 迭代 → golden + 实时双验证。**只做现有语义原语的 UI**（ignore reason / 记忆确认忽略封禁 / pattern 反馈 / golden label），不引入第三套标注。golden 审查：种子列表（accepted/ignored 子集）+ trace 链视图 + label 编辑落库 + baseline 重跑按钮（替代 JSON 硬编辑）。

#### 10. 无状态输入原则（stateless-input，横切铁律）

**算法产出的、将进入 LLM 判断的内容，必须是陈述性事实（无状态文本）——检测到什么活动、任务 X 处于 waiting、上次活动时间、未用材料数——不含任何指令性结论**（"应该继续 X"、"建议采纳"）。理由：LLM 有采纳倾向（sycophancy），喂结论 = 走形式确认，LLM 极少否决。**LLM 是唯一建议来源**（LLM 模式）；算法只在**算法模式**（无 LLM，算法即决策者）下直接产建议。审查项：`buildContext` 是否把算法置信度/排序喂给 agent——若喂了有同样偏置风险，列为后续审查。

### 四、任务质量

#### 11. 任务资格门（Task Quality Gate）

候选生成之前、聚类之后的纯规则门：**时长门槛**（簇时长 < 阈值不成候选，默认 3–5 分钟，**算法层常量不进用户设置**，跟可成长算法走；用户标记 + 算法自协调）；非任务内容由名单模式（决策 4）+ prompt 规则共同拦截；坏候选仍进时间线/证据可见，不丢数据。与"琐碎块拼装"（out of scope，未来把短块收集拼到正经任务上）配套。

#### 12. 双主题预防门（Dual-theme Prevention Gate）

**预防而非事后拆分**：位置在聚类与候选生成之间——候选生成时已无双主题结构，AI 耦合（标题生成）之前拦截。确定性信号：**簇内时间分布（主信号）**——高频在 2–5 应用间切换 = 同一任务；大块孤立停留（30/60 分钟级、无高频折返）= 疑似双主题（应用集分裂**不作为**信号：跨应用切换是常态，会误伤）；**标题一致性（辅助）**——簇内标题关键词重叠低 + 时段双峰佐证。疑似 → **本地模型把关**（开：语义裁决，拆成两子簇各自成候选；关/失败：不自动拆，标"疑似双主题"进工作台供标记）——不能纯靠算法（不变量 H 保持：本地模型关 = 纯算法等价）。

#### 13. 去重两层

- **脚本层**：候选标题 vs 现有任务标题相似度比对（归一化后），太像不进候选
- **AI 层**：现有任务清单**主动**进 prompt（不是"可搜索"而是"已列出"），AI 自行剔除与现有任务重复的候选；输入为中性事实（决策 10）

#### 14. 标题规则

**应用名永不进标题**：标题只讲"做什么"，应用在 apps 字段（任务本身已含应用）。由 suggestTitle 的 prompt 规则 + 资格门的标题结构启发式共同保证。

#### 15. 用户画像填写 UI

设置 tasks tab AI 配置区新增画像填写（职业/自我介绍）；保存写 memoryGraph `source='user'` profile fact，接通记忆面板 explicit 区（当前恒空，无写入路径）；预填门控挂 memoryAccess，不另立开关。onboarding 画像引导 out of scope。

### 五、任务生命周期（Dia 借鉴）

#### 16. 暂停任务重新激活（Reactivation，未完成工作推断）

候选 C 应用集覆盖率 ≥0.6 命中任务 T 时按 T 状态分叉：running → L3 丢弃（现有）；**waiting → 重新激活**：候选不展示，证据（窗口标题/应用集/材料）挂到 T 上，推 reactivation 建议走 **L1 指示器通道**（"检测到与任务 X 类似的活动，要继续吗？"）；paused（用户手动）→ **免疫**（域层规则已有），候选照常 L2；completed/archived → 不复活，按新相似任务走正常候选。冷却 = recommendationHistory 复用（任务指纹，24h 默认，ignore 抑制）；接受 → `transition(T, 'running')`。

#### 17. 建议动作化表达

reactivation 与建议的正文 = **确定性推导的 next action**，不进 LLM 热路径（纯算法优先）：未用材料数（"有 N 条关联内容可粘贴"）、上次会话结束窗口与时间、候选合并证据。LLM 只做措辞润色（可选，无状态输入原则约束输入）。

#### 18. 完成感（Completion Fade）

系统**提议**完成（waiting + 连续 N 天无活动，N 为算法层常量）→ 用户一键确认 → completed → **淡出动画**退场（任务详情完成态）。不静默自动完成——系统提议、用户确认，trace 落决策（不变量 I 可追溯）。

### 六、入口与记忆

#### 19. 智能初始页面（Smart Landing）+ 可成长算法

设置初始页面下新增"智能"选项：**线索打分 → 视图切换**，纯确定性、无 LLM 热路径（面板展开是即时事件）：

- 前台窗口应用亲和（Explorer → 文件 +5；编辑器/浏览器 → 剪贴板 +2；映射可配置）
- 最近内容事件（5 分钟内拖入/拖出文件 +4；刚复制链接/图片/文本 → 对应 filter +4/+3；**线索衰减**代替固定窗口——越近越强，半衰期分钟级）
- **焦点在输入框** → 剪贴板 +4（信号来自 UIA 摄取 `FocusedElement` 类型——与决策 1 同一条采集链）
- L1 候选在等 → 候选 +3
- Morning Brief 日（决策 20）→ 最高权重线索

无线索 → 回落现有 restore/landing（与"稍缓/持久"语义区分：restore 是记忆，智能是预测）。**可成长算法**：展开后 N 秒内（默认 3s）切换视图 = 预测失败负样本，停留或执行预测动作 = 正样本；反馈进 trace（`kind='landing'`）→ 工作台可视化命中率（按线索源分组）→ 前期人工调分、后期自动化。理想态：用户零设置，系统按使用情况自协调。

#### 20. Morning Brief（晨报）

跨日边界检测（距上次面板关闭 ≥6h 的首次打开）→ **本地确定性预组稿**（读 TaskStore/suggestionEngine/activityLedger/memoryGraph，零 LLM、零云端——Dia 的 token 门槛与"后台 AI 拖慢浏览器"负面是其反面教材）→ 首次打开落地为 Brief 视图。内容五块：①未完成任务（waiting + 最近活跃，含 reactivation 候选）②未用关联材料提醒（read-later 等价物）③昨日未决候选 ④昨日动作摘要（top 段/簇按时长）⑤可选个性化一句话（本地模型；无 LLM 时模板兜底，输入遵守决策 10）。**开关第一天就有**（Dia 早期"不知道怎么关"是核心负面）；实验性姿态明示；手动"生成今日简报"路径（/morning 等价物）；全天可回看、to-do 可勾选（勾选 → 决策 18 完成感）。

#### 21. 记忆溯源链（Memory Provenance）

级联删除（决策 4）与工作台记忆过程视图（决策 8）的前提：fact 需与来源绑定。当前 memoryGraph fact 只有 type/content/source（来源类型），缺"从哪些 episodes 蒸馏而来"。**fact 增加 `originEpisodes`（来源 episode id 列表）+ 来源应用集/时间窗**（episode → events → apps 链已存在，补齐 fact → episode 一环）；级联删除复用 invalid_at 语义（不覆盖）；多来源 fact（LLM 蒸馏常混合多应用）任一来源存活则保留，否则级联，工作台标"混合来源"供裁决。memoryGraph schema 变更。

## 后果

- **P0 排期**（实现顺序）：①AI 依据修复（决策 5）②trace 契约扩展（决策 6，algorithm/model 落库）③工作台 v1（决策 7/8/9，dev 模式 + 三视图 + 标记）④资格门 + 双主题预防门（决策 11/12）⑤智能 landing + 可成长（决策 19）⑥画像 UI（决策 15）⑦reactivation + 完成感（决策 16/18）⑧Morning Brief（决策 20）⑨溯源链（决策 21）
- **挂起项**（不阻塞主线）：网站级 URL 规则（等 URL 数据源）；琐碎块拼装（out of scope，未来）；golden 工作台审查细节（见原型定）；白名单自动发现（可选）；非工作应用与娱乐属性的权衡（由名单模式 + 网站级规则承接）；`buildContext` 置信度偏置审查（决策 10）
- **横切铁律**（新增）：决策 10 无状态输入原则与 ADR-0005 原则 2/7/8 并列——AI 无决定权、推断可解释、被拒数据不进 Agent、**算法不引导 LLM**
- 纯文档票：本 ADR 不引入代码改动，作为后续实现的指导依据
