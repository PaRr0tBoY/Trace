# ADR-0005: 架构原则（活动 → 决策 → 记忆流水线）

- 状态：已接受（2026-08-12，grill-with-docs 会话）
- 关联：ADR-0004（任务层术语：候选任务 / 任务决策）；spec（Trace AI 管道重构规格，本 ADR 为其原则成文）

## 背景

本波重构把"单个建议引擎包办一切"拆成**活动 → 决策 → 记忆**的明确流水线。流水线横跨多个模块
（采集、聚类、决策、记忆、隐私、AI 依据）与多种实现者（Agent、本地模型、纯算法），若不在动手前
先落定架构原则，实现中途极易改弦更张。本 ADR 记录八条原则，作为后续所有实现的指导依据；
实现层面的选择（模型量化、调用次数、冷却时长、触发条件、滞回参数等）不进入本 ADR，见 spec。

## 决策

### 1. ActivityLedger 中间层

采集事件持久化为证据时间线后不直接喂给 AI：聚类模块（ActivityLedger）把一段行为证据整理成
**活动（Activity）**——应用集、窗口标题、活跃时长、剪贴板材料与归属目标——活动是 Agent 拼装
提案的输入积木，Agent 不直面原始事件。动机：原始事件细碎、低语义，单次应用切换或复制说明不了
什么；活动是"一段行为"的稳定抽象，聚类负责归并，AI 只消费整理后的观察对象。活动是观察对象、
任务会话是解释对象（1:N 不一一对应）；活动不持久化、不入 UI，但记录版本信息（classifierVersion /
promptVersion）供追溯，且任何活动可回溯到构成它的事件。聚类与 AI 因此解耦：改聚类不影响 Agent，
改模型不影响聚类。

### 2. Agent 判断不改核心状态

**AI 无决定权**：Agent、本地模型、纯算法都只产出提案（任务决策 / 候选任务），任何状态转换——
任务新建、切换、暂停、会话开始与结束——都由确定性的状态控制器验证后执行；决策者只提"想做什么"，
状态机决定"能不能做、怎么做"。动机：状态诚实且可解释——状态标注来源（user 手动 / system 推断）
与原因，UI 可区分"你暂停了"与"系统判断等待中"；不变量（全局唯一 RUNNING、runningTaskCount ≤ 1、
PAUSED 免疫自动恢复）由确定性代码强制，而非依赖模型判断的稳定性；即使模型幻觉或调用失败，
状态机也不会被破坏。三种决策者实现同一接口，外层不感知决策者是谁。

### 3. Memory 三表时间上下文图

长期记忆只有三类表：**episode / entity / fact**。画像、模式、任务记忆、偏好等概念一律作为
fact 的 type / source 字段，不建独立表；事实带时间有效性（valid_at / invalid_at / expired_at）、
来源（episode 链）与用户状态（confirmed / suggested / ignored / banned）。动机：概念收敛——
"画像"与"模式"不是新的存储类型，只是事实的分类；任何长期记忆都能回溯到它来源的 episode；
UI 的记忆分组只是按 fact type 过滤的视图，不是不同的存储。

### 4. SQLite canonical

本地 SQLite 是**唯一事实源（canonical store）**：证据时间线、记忆、AI 依据等结构化数据都以
SQLite 为真相，任何辅助文件（如 JSONL）只作 crash-safe append、诊断与导出输入，不与数据库平级。
动机：查询、全文检索、保留期清理与事务一致性需要真正的数据库而非手写 JSON 文件；单一事实源让
"两份数据不一致时信谁"的问题不存在——任何活动可回溯至事件、任何决策可追溯，都依赖这一点。

### 5. 本地模型可选

本地模型是嵌入产品内部的**可选增强**：默认关闭，关闭或失败时功能等价可用——纯算法路径照常
工作，本地模型不构成必需依赖。动机：AI 是增强而非产品前提，不强行增加安装体积（模型按需下载）；
把"有模型"设为前提，会把 AI 的可靠性变成产品的可靠性。

### 6. 无 Ollama

不依赖任何**外部运行时**：Ollama 这类独立推理服务已从产品中删除，模型能力要么嵌入产品内部
（本地模型），要么走用户自配的云 provider。动机：外部运行时是安装负担与故障点——用户要先装
第三方服务才能用某功能，违背"嵌入产品内部"的定位；产品应开箱即用，或干脆不用。

### 7. 隐私三权

隐私控制是**三个权限面**：采集（Capture）/ AI / 记忆（Memory），各自独立开关、集中一处管理；
证据深度（L0 元数据 → L4 历史）与隐私敏感度是**两个正交维度**，不合并成一个整数——数据可以
"深度高但敏感拒看"（一张截图可以是 L3 深度但 privacy=denied）；被拒绝的数据绝不进入 Agent
（连预填也过门），隐私拦截行为被记录并标注，算法层的本地功能不受隐私门影响。动机：采集 / AI /
记忆对应数据生命周期的三段——进、出、存——各自可控，用户一处掌控；正交维度让"能看但拒看"
可表达；"被拒数据绝不进 Agent"是信任底线的硬边界。

### 8. AI 依据解释基础设施

任何 AI 决策都**可追溯**：观察到什么、召回了什么、为什么这么判断、结果如何（采纳/忽略），连同
版本信息一并记录；用户在提案卡 / 任务详情可查看依据，开发者可导出完整处理链条报告。动机：信任
可建立——"建议从哪来、看到了什么、为什么"有据可查；可回归——改 prompt、换模型后历史判断为什么
变，凭版本信息可解释。依据不是事后日志，而是与决策同生命周期的解释基础设施。

## 后果

- 八条原则约束本波全部实现；实现细节（量化、调用次数、冷却时长、滞回参数、触发条件、模型名等）
  见 spec，不进入本 ADR。
- 原则 2 / 7 / 8 构成铁律：AI 无决定权、推断可解释、被拒数据不进 Agent。
- 纯文档票：本 ADR 不引入代码改动，作为后续实现的指导依据。
