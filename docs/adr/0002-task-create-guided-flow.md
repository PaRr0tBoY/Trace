# ADR-0002: 任务创建/编辑引导流（渐进式披露）

- 状态：已接受（2026-08-11，grill-with-docs 会话）
- 关联：ADR-0001（剪贴板归属）、ADR-0003（AI 标题并入保存按钮）

## 背景

原 TaskEditor 新建任务只有"标题 + 备注 + ✨建议标题"三件套，AI 建议时没有任何可依据的
上下文（`task=null` → appNames/resources 全空），等于从 0 编标题。用户要求：点击新建任务
后有一个渐进式引导过程，把"这个任务跟哪些窗口、哪些剪贴板内容相关"先问出来，AI 建议才有
依据。

## 决策

新建与编辑共用同一个表单（TaskEditor 重写，双模式）。布局自上而下：

1. **任务标题**（第一行输入框）。
2. **进程选择器**（第二行）：平铺图标网格，多选。集合 = **L0 窗口跟踪捕捉过的应用**，
   数据取 事件总线 AppSwitchEvent 并集 ∪ 剪贴板 sourceApp 并集（本就同源同门控；sourceApp
   持久化保证重启后集合稳定，事件总线补充"最近活跃但没复制过"的窗口）。无剪贴板条目的
   应用也可选——任务不一定需要剪贴板内容。不显示条目数角标。
3. **剪贴板列表**（第三行）：
   - 初始显示最近 3 条（任意进程，capturedAt 降序）。
   - 选中进程后，候选集 = 3 条锚点 ⊕ 所有选中进程的其余条目，**单列表、按时间降序、
     去重**（同一 id 只出现一次，锚点位置优先）。
   - **每次点"显示更多" +3 条，15 条封顶**；列表溢出时滚动。
   - **每条显示来源进程图标**（sourceApp），无归属的条目无图标。
   - 多选；已选条目打勾。
4. **备注输入框**（列表最末尾）。
5. 底部：**保存**（AI 集成见 ADR-0003）+ 取消。

### 保存语义

- 选中进程 → `task.apps`（AppRef：id = 规范化 exePath，name，exePath）。
- 选中剪贴板条目 → `task.resources`（`buildClipboardRef` 快照，main 侧构建）。
- 进程/剪贴板/备注均可为空；**四项全空时保存按钮禁用**。
- `task:create` IPC 扩展为可带 apps 与剪贴板 itemIds（快照在 main 构建，renderer 不碰
  原始内容）；`task:update` 的 TaskPatch 扩展支持 **apps 整体替换 + clipboard resources
  整体替换**（files 类 resources 不受表单影响，保留）。

### 编辑模式（与新建同表单）

- 预填：apps = task.apps（选中态）；剪贴板候选 = 3 条锚点 + task.apps 的条目 + 已关联的
  clipboard 条目（含已从剪贴板移除的 dead 快照，置灰显示）；勾选态 = 已关联的 clipboard refs。
- 保存 = patch.apps（替换）+ patch.resources（clipboard 部分替换，files 保留）。

## 后果

- 渐进披露成立：先给最少信息（3 条），选择产生更多选择（进程 → 该进程条目）。
- AI 建议永远有上下文可用（见 ADR-0003）。
- 创建即带 apps 的任务会立刻参与 attribution：前台切到所选应用时任务自动 resume/刷新
  lastActiveAt——手动创建 = 显式声明归属，符合任务系统语义。
- v1 不额外持久化"见过的应用"表；重启后进程集合暂时只剩 sourceApp 并集，随事件积累恢复。
  若用户后续反馈集合缩水不可接受，再加 seen-apps 持久化（独立 ADR）。
