# 21 — 输入框焦点修复

**What to build:** 面板窗口 `focusable: false`（upstream 遗留）导致所有输入框不可聚焦、键盘输入落到外部窗口。改为：点击输入框时激活面板窗口让键盘输入落位，其余交互保持零打扰。

**Blocked by:** 无

**Status:** ✅ done（2026-08-11）

## 最终方案（实测驱动的三版迭代）

**平台死路（全部真机实测）：**
- `focusable:false` + user32 `SetFocus`：koffi `GetFocus` 确认线程焦点已设，但 `keybd_event` 全局按键仍去前台窗口（0 个 keydown 到达 renderer）——SetFocus 只改线程焦点。
- `focusable:false` + `element.focus()`：静默失败，无 focusin（死锁）。
- `setFocusable(false)`：Windows 上**隐藏窗口**（Electron 副作用），面板无法再展开。

**最终实现：**
- 窗口常驻 `focusable:true`（window.ts），OS 可激活性由 koffi `WS_EX_NOACTIVATE`（`GetWindowLongPtrW`/`SetWindowLongPtrW`，`electron/main/focus.ts`）控制。
- 输入链：renderer `focusin`/`pointerdown`（App.tsx，捕获阶段，editable 匹配）→ `ui:input-focus` → main 剥 NOACTIVATE + `win.focus()`（+ `setSkipTaskbar`）。
- **激活按会话保持**：输入框 blur 不释放（切换输入框零闪烁），面板关闭（`window:set-interactive(false)`）才贴回 NOACTIVATE。
- `onWindowBlur` 主动 blur 输入框：防 Chromium 在窗口重激活时重放 focusin 误触发激活（实测重放会发生）。
- pointerdown 非输入元素 → `ui:input-blur` → `win.blur()` 立即失活：Chromium 对 focusable:true 窗口任何点击都会激活（NOACTIVATE 拦不住，实测），非输入点击后必须主动还焦点。
- `lastPointerOnNonInput` 标志阻断焦点重放与失活请求对抗。

**验收（真机 SendInput 实测）：**
- [x] 点击输入框 → 激活 + 键入生效（keydown 到达、value 变化）
- [x] 切换输入框 → 无 wblur、无闪烁、无窗口反复弹窗
- [x] 面板关闭后窗口保持可见（blade 态），hover 可重新展开
- [x] 正在别处打字时点卡片/按钮 → 前台不变，焦点不抢（fg 保持原窗口）
- [x] Escape 不误触面板关闭（useEdgeHover onKeyDown 既有逻辑）
- [x] typecheck 全绿 + 358 测试通过
